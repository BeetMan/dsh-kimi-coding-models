# Kimi Coding 0.7.4 回归问题

对应提交 `6d32201`。**两项均已修复**（见各节末尾）。

## 1. 平台选择器把混合端点显示为官方预设

模型目录使用中国版默认地址、额度地址使用自定义代理时，设置页仍显示“中国版”。此时再次选择“中国版”不会触发回填。用户可能以为已恢复官方设置，但聊天窗口刷新额度时，Host 仍会把配置的凭据发给原代理。

**修复建议**：用模型目录、额度和路由 Base URL 三个字段共同判断当前预设。只有三个地址全部匹配时才显示对应平台，其余组合显示“自定义”。从“自定义”选择中国版或国际版时，一次性回填三个字段，保存后生效。[平台选择逻辑](../client.js#L968-L988)

**修复状态**：已按建议实现。三个端点全部匹配预设才显示对应平台；任何混合组合显示不可选的「自定义（混合端点）」选项；从「自定义」切换到中国版/国际版时一次性回填三个字段。提示文案同步说明了混合状态的显示规则。

## 2. Host 测试缺少新增的 `platform` 字段

在 DeepSeek Harness 运行时执行 Host 测试，首个 HTTPS 断言即告失败。测试配置缺少 `platform`，而 `currentConfig` 会对每个声明的字段调用 `.get()`，因此抛出 `TypeError`。后续的凭据传输、空目录删除确认和并发同步用例均未执行。

**修复建议**：在 Host 测试配置中补上与插件默认值一致的 `platform: 'china'`。使用可加载 DSH 的运行时执行该测试，确认安全断言全部通过且测试未被跳过。[测试配置](../test/host.test.mjs#L19) · [Host 配置读取](../index.js#L110-L112)

**修复状态**：已补上 `platform: 'china'`。本环境（普通 Node 无法解 asar 锚点）该测试按预期跳过；需在可加载 DSH 的运行时复跑确认全部断言通过。
